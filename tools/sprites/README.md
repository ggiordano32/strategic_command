# Sprite pipeline (steps 1a-1d)

Units are written as data in `spec.json`; Blender builds them from code and
renders the frames; `pack.py` makes the sheets and the manifest the game
reads. No hand modelling, no downloaded models.

```
spec.json          units (parts lists), rigs, bodies, materials, palettes, atlas sets, iso test
fmt_spec.py        rewrites spec.json in its compact style after a scripted edit
build.py           Blender script: meshes, armature, actions, renders (3 passes a frame)
pack.py            stdlib Python: outline, crop, atlas, manifest, game tables (+ --contact preview)
preview/           Godot scene: the atlas recoloured per palette at 3 zooms, iso 8 directions
iso/               iso test sheets (.gdignore'd: not in the game)
_frames/           raw renders (git-ignored, .gdignore'd)
../../assets/sprites/   atlas_shade.png, atlas_mask.png (+ .import), manifest.json
../../game/sprite_atlas.gd, sprite_frames.gdshaderinc   GENERATED by pack.py
```

## Run

```sh
# all units + the iso test (about 14 s on the RTX 3070, EEVEE; the first run
# after a driver / Blender update adds ~10 s of shader compiling)
~/.local/bin/blender -b --factory-startup -P tools/sprites/build.py 2>&1 | grep -v Saved:
#   options after --: --units heavy_swords,spearmen   --no-iso   --iso-only   --out DIR
python3 tools/sprites/pack.py            # ~1 s; --contact /tmp/x.png for a quick look
godot --headless --import                # re-import the atlas after a change
godot --path . --resolution 2400x1350 res://tools/sprites/preview/preview.tscn
#   -- --shot=/tmp/top.png [--scroll=520]   screenshot and quit
```

Render times (2026-10-13): heavy_swords 2.3 s, spearmen 1.9 s,
shock_cavalry 2.1 s (14 frames x 3 passes each), iso 8 directions x 6
frames x 3 passes 7.0 s. Output 184 KB in all.

## Add a unit (spec only)

1. Under `units`, add an entry: `rig` (`humanoid` or `horse`), `body` (the
   shared parts list under `bodies` the unit wears), `render_box` (metres
   around the man's feet, x0 x1 y0 y1, multiples of 0.25 m; generous: the
   packer trims per action), and `parts`. A mounted unit adds `rider`
   (`rig`, `body`, `seat`, `parent_bone`) and `rider_parts`.
2. A part: `n` name, `bone` it follows, `mat` (a fixed colour from
   `materials`, or `primary` / `secondary` / `accent` for faction-coloured
   parts), `shape` and its sizes:
   - `box`: `pos`, `size` [x y z], optional `bevel`, `rot`
   - `sphere`: `pos`, `r`, optional `scale`, `verts`
   - `cyl`: `pos`, `r`, `len` (along local Z; `rot` [0, 90, 0] faces it forward), `verts`
   - `limb`: `a`, `b` end points, `t` thickness (or [width, depth])
   - `cone`: `a` base, `b` tip, `r`
   - `scutum`: `pos`, `size` [thickness, width, height], `bend` radius
   Coordinates are the rig's rest pose in metres: +X forward, +Y the man's
   left, Z up (the man stands at the origin, hands at about 1.1 m: left
   hand 0.38, 0.28; right hand 0.34, -0.29). `rot` is Euler XYZ in degrees
   (about Y, positive tips the top forward: a shield tilted back to show
   its face is negative). `mirror: 1` adds the right-side twin.
   `pattern: 1` marks cloth that carries a faction's check.
3. Run build (with `--units yourunit --no-iso` while iterating) and pack.
4. To use it in battle: add its key to `atlas.sets` in spec.json (the
   order is the set id: 1, 2, ...; append, never reorder), pack, import,
   and set `"sprite_set": <id>` on the unit rows in `sim/unit_types.gd`.

## How a unit row gets its sprite (step 1b)

`sim/unit_types.gd` rows carry two view-only fields: `sprite` (the
procedural sprite drawn by `game/soldier_layer.gd` `_make_atlas`) and
`sprite_set` (0: use `sprite`; n: set n of `atlas.sets`). Today: 1
heavy_swords (heavy and light lines, all tiers and faction variants), 2
spearmen (spear lines), 3 pikemen (pike lines), 4 shock_cavalry (cav,
cav_missile, general lines). Set it on the base row of a line and its tier
and faction rows inherit it. 5 archers (archer line), 6 javelinmen, 7
slingers, 8 gastraphetes (step 1c: unit `pose` variant archer / javelin /
sling / belly, `cord` parts, `show` / `hide` frame lists). Step 1d: 9 elephant,
10 camel, 11 camel_archer, 12 crew (every battery, tower engine and wagon
crew row), and on artillery rows a second field `engine_set` for the
engines (13 bolt_thrower: bolts and tower bolts, 14 stone_thrower: stones
and tower stones, 15 scorpion). The set fields are 5 bits (31 sets). `atlas.props` (cart, wagon, draft_horse)
are packed too but not in the shaders' table: `PROPS` in sprite_atlas.gd,
drawn by game/overlay.gd (wagons). Still procedural: dogs, characters,
siege equipment (ladders, ram, tower, mantlets). The palette is the unit's faction's (palette keys = the
faction keys of `campaign/cdata.gd`, in its FACTIONS order); see
`game/soldier_layer.gd` `_palette_rows`.

West pack sets (2026-10-15, ids 16-26, wired 2026-10-16: see docs/STATUS.md
"West sprites"): 16 musketeers (tricorne, coat, sash, bandolier, musket; pose
`musket`: gun on the spine, forearms turned in, flash on attack frame 1), 17
w_pikemen (morion, buff coat, 5 m pike), 18 buccaneers (bandana, hide vest,
machete, 2 m fusil; pose `musket`), 19 rodeleros (morion, cuirass, rodela,
rapier), 20 cutlass (headscarf, sash pistols, cutlass + boarding axe), 21
lancers (horse, slouch hat, cuirass, lance), 22 pistoleers (horse, long
coat, pose `pistol`: both arms out, flash on frame 1), 23 native_warriors
(feather ring, paint, shield, macuahuitl), 24 native_bowmen (archer pose), 25
w_crew (gun crew, `crew` pose), 26 cannon (engine set, rig `cannon_engine`,
anim `cannon`: attack 0 loaded, 1 fired and recoiled, 2 / 3 run out; carriage
in the primary colour). The shader look is 5-bit sets (set + 32 x palette; the engine set
in texture block 8); pack.py allows 31 sets and 16 palettes. Palettes 9-16: new_spain,
tierra_firme, england, france, dutch, brethren, itza, miskito. Render about
2 s a unit, the 11 sets 25 s; atlas now 1024x1804, 913 KB of PNG.

Rigs name their animation set (`anim`: humanoid, horse (also the camel
rig), elephant, bolt / scorpion / onager (engines), cart / wagon (props)).
A unit may carry `riders` (a list: prefix, rig, body, seat, parent_bone,
parts, pose, `stand` 1 = on his feet, `fall` "roll" = stays on the beast in
its death, skip); step 1b's `rider` + `rider_parts` still works. Cords
take `via` without `show` (always). Engines' attack frames are picked by
the game from the reload (0 loaded, 1 released, 2 / 3 winding), not the
clock. `pack.py --contact-units a,b --contact-palettes rome,gauls` and the
preview's `--units=` / `--palettes=` narrow the views.

Animations are code, shared: `humanoid_pose` and `horse_pose` in
`build.py` (idle 1, walk 6, attack 4, death 3 frames; frame counts and fps
in `spec.json` `actions`). Palettes are `spec.json` `palettes` (copied into
the manifest).

## Outputs and conventions

- 24 px per metre (`ATLAS_PX_PER_M` in `game/soldier_layer.gd`), 0.0417 m a
  pixel; an infantry man fills about 1.2 m (29 px) at 1x.
- Top view: the man faces image right (+x forward); his left is image up
  (the game's local y "to the right" is image down). The anchor in the
  manifest is the man's feet (the unit's origin) in px from a frame's
  top-left; each action has one frame size and one anchor.
- Atlas: frames start on `atlas.align` (4) px steps with `atlas.gutter`
  (4) px of empty border (mip levels up to 2 never mix frames); per set and
  action one entry (x0, y0, w, h) + (anchor x, anchor y, step, frames).
- Shade sheet: lit colours, faction parts lit white, a 1 px dark outline,
  hard alpha. Mask sheet (same layout): R primary, G secondary, B accent,
  A = 255 - 128 x check; recolour in `preview/recolor.gdshader`.
- Determinism: fixed EEVEE samples (16), no random; the same Blender and
  GPU give the same bytes.
- The game loads the imported atlas (lossless, mipmaps, no alpha-border
  fix: the shade's empty texels are already outline-dark); the preview
  reads the PNGs directly.
